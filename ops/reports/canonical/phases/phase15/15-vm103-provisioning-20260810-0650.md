## Debugging lessons (documented for future VMs)

1. **cloud-init needs `ipconfig0=dhcp`**: PVE's cloud-init generated a network-config with only a DNS block (no physical interface) when no ipconfig0 was set → ens18 never came up → no DHCP, no SSH, no agent. Fix: `qm set <vmid> --ipconfig0 ip=dhcp`.
2. Boot "hang" at the Debian splash was actually systemd-networkd-wait-online blocking boot for ~2 min (expected when networkd config is absent) — not a crash. Check the journal (`journalctl --root=...` via kpartx mount) before assuming a hang.
3. `qm reboot` fails without the guest agent; use `qm stop`/`qm start`.
4. Debian cloud images ship `disable_root: true` — remove via cloud.cfg edit (mounted disk) or set `--ciuser root` (which cloud-init honors by setting disable_root false in user-data; verify in the generated user-data).
5. Genericcloud image lacks qemu-guest-agent and serial getty; use the `generic` image for PVE.
6. LVM storage needs raw disk format — `qm importdisk` with default format; qcow2 fails with "illegal characters".
7. On shared LANs, `ip neigh`/ping sweeps can match unrelated devices — confirm MAC before SSH attempts.
