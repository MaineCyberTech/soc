# Active Response Audit Workflow

## Purpose

Verify every active-response action is visible, attributable, and reportable.

## What is audited

- Rule 651: Host Blocked by firewall-drop Active Response (command executed)
- Rule 652: Host Deleted from firewall-drop Active Response (unblock)
- Trigger rules: 5710 family (sshd brute force)

## Audit procedure

```bash
/opt/mct-security-stack/ops/scripts/active-response-audit.sh
# -> reporting/output/active-response-weekly.md
```

Weekly report shows: total events, top rules, top agents.

## Manual checks

1. Confirm block counts look sane (spikes = brute force campaigns).
2. Confirm unblocks (652) follow blocks (651) within the block duration.
3. Confirm no AR fired against internal/trusted IPs (would indicate misconfig).
4. Escalate repeated AR loops to IRIS (Class A if persistent).

## Query reference

```json
{
  "size": 0,
  "query": {
    "bool": {
      "filter": [
        { "terms": { "rule.groups": ["active_response", "active-response"] } },
        { "range": { "timestamp": { "gte": "now-7d/d" } } }
      ]
    }
  },
  "aggs": {
    "by_rule": { "terms": { "field": "rule.id.keyword", "size": 20 } },
    "by_agent": { "terms": { "field": "agent.name.keyword", "size": 20 } }
  }
}
```

Note: Wazuh group name is `active_response` (underscore) - both spellings queried.

## Safety

- Audit is read-only; no AR triggers generated by the audit itself.
- Real brute force never performed as part of the audit.
